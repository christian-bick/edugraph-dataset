01 / FINDING

Both improvements are feasible, with different safeguards.

Consolidate mechanics

The branch already shares canonical range semantics and resolves compatible label choices before generation. The repeated work is the connection between quantity meaning, feasible numeric configurations and conditioned sampling. A shared adapter can standardize that connection.

Keep task semantics explicit. Fraction part counts, syntax-only expressions and shown currency amounts cannot be recovered reliably by scanning every numeric field.

Minimize what the model must predict

Use a compact signature of the mathematical competency, requested performance and meaningful constraints. Retain complete source provenance, numeric facts and contextual claims alongside it.

Measure retained distinctions. A fixed label budget or blanket removal of ranges loses information that current standards explicitly require.

Recommended first step: pilot the numeric adapter without changing semantics, then run a separate, non-publishing experiment for the compact annotation profile. Combining these migrations would obscure whether differences came from generation or policy.

This review inspected current source, pinned ontology definitions, authored K–6 CCSS targets and official standards. It ran a read-only label deletion analysis. It did not change generators, targets, the ontology, training data or production annotation rules. The established-rule overview remains a separate reference.

02 / NUMERIC RESOLUTION

A shared domain adapter, feeding the current planner

The reusable foundation is already present: canonical witnesses enforce tight absolute bounds; 45 range profiles encode correlated choices; schema-choice metadata and compatibility planning select admissible configurations. Planned generation separates choice entropy from mathematical and presentation entropy.

A · DECLARETask contract

Native domain + quantity roles + source constraints + applicable label facets.

B · COMPILEFeasibility metadata

Exact admitted profiles and dependencies for the existing planner; no random draws or eager large pools.

C · GENERATEPrepared conditional domain

Lazy preparation, original sampling law and independent witness verification.

Standardize these responsibilities

  1. One range catalog. Reuse one threshold-to-descriptor mapping across target expansion, canonical resolvers and validation. The current threshold table, descriptor table and legacy boundary resolver repeat related knowledge. Preserve the distinction between an inclusive interval and a tight canonical profile.
  2. Typed quantity evidence. Record exact value, role, unit and why it participates: primary operand, required result, prescribed intermediate, or independently assessed count. Keep integers, rational values and scaled decimals exact where boundary tests require it. Use separate evidence selections for range, sign/zero and operand-role constraints: absolute magnitudes cannot establish sign, and MultiplesOf10 concerns both primary operands, including a required unknown. Presentation-only glyphs and storage units are separate.
  3. One feasibility definition for matching and drawing. The same admitted domain must support both a cheap, exact admits(config) query and a lazy prepare(config) operation. Advertised configurations must have nonzero support. Correlated width, sign, zero, divisibility and range constraints belong in this shared definition.
  4. Several sampling backends behind one interface. Small finite catalogs, constructive integer intervals and weighted/decomposed large domains need different implementations. Preserve support, multiplicity, conditional probabilities and random-draw order; a universal uniform sampler would change the dataset.
  5. Explicit failure states. Distinguish an impossible configuration, an unsupported ontology band, a policy exclusion and an invalid declaration. Multiplication overflow and algebra range omission have different reasons, although both can produce no range labels.
NumericDomain<Config, Prepared, Task>
  choices / dependencies     // finite metadata from the shared constraint definition
  admits(config)             // exact feasibility; no randomness
  prepare(config)            // lazy domain preparation
  sample(prepared, rng)      // native conditional law and replay behavior
  quantities(task)           // reviewed values, roles, units and evidence

Independent verification:
  check declared claims against the task's mathematical witnesses

Metadata compilation should be explicit or precomputed where expensive. Do not invoke arbitrary value resolvers during matching: the current static-resolution boundary permits only reviewed deterministic contracts. Retain connected choice groups and their existing planning bound. Preserve original-request constraints separately from completed labels: a newly precise width claim must not silently select a different native operand pool. Direct and planned resolution should both be feasible and truthful; their distinct selection distributions need not become identical.

Existing patterns to extend

Integer pair sampling already shares feasibility plans with generation. Unit-equivalence profiles share resolver and compatibility construction; their domain metadata avoids constructing pools during catalog load.

What stays task-specific

Fraction relation versus derivation quantities, shown currency units, counting totals versus enumeration, and syntax versus calculation remain reviewed mathematical contracts. The adapter makes their declaration consistent; it does not invent their meaning.

How much repetition is visible?

A bounded textual inventory of 568 production generator TypeScript files found canonical-range imports in 160 files across 91 leaf modules, 23 module profile files, witness-field validation patterns in 55 files, explicit range-domain cache patterns in 45 files and subtractive weighted-selector patterns in 24 files. These are syntactic opportunity indicators, not proof that the implementations are interchangeable. The inventory records individual files and hashes.

03 / PROPOSED RULESET

Minimal means sufficient evidence, not the fewest labels.

Use three explicit layers. The current flat annotation stream remains authoritative until a replacement is approved and validated.

LayerPurposeExample
Generation factsFull numeric constraints and witnesses, including facts that are not training labels.An algebra task still has bounded coefficients and a reproducible generator, while its range labels are excluded.
Observable claimsComplete justified Area, Ability and meaningful context; units and methods remain explicit.Fraction comparison, the requested justification, common denominator, visible model and actual unit.
Training profile
Proposed		A versioned projection of those claims, with per-facet applicability and omission reasons.Competency/action labels plus selected task constraints; other evidenced context retained in a separate channel.

This is compatible with the ontology’s distinction between direct claims and derived information, but it is an application-level proposal. ONT-E4 still requires meaningful context even if a particular search does not need it. Calling a reduced training projection a complete ontology annotation would hide that obligation.

  1. Start with the demanded performance. Identify what the learner must do and what the content makes accessible. A visible equation is not automatically equation writing; an available product is not automatically evaluation. Keep every independently justified Area/Ability, without imposing a fixed count.
  2. Decide applicability before choosing a value. A reviewed task-family rule determines whether range, sign, width or another facet participates. Apply explicit exclusions first. Base this rule on observable mathematical form and instructions, never a hidden grade, standard ID or generator name.
  3. Retain a constraint when it preserves a justified contrast. Protect a source competency distinction or an independently observable task-complexity distinction: unlike denominators, unknown role, regrouping, number kind, step structure, required method, units or representation changes. Do not keep a feature solely because it predicts the grade in this dataset.
  4. Separate source requirements from practice cohorts. “Compare three-digit numbers” is a source constraint. A later-grade practice pool beginning above 1,000 may be a sampling decision. Record both origins; a cohort choice must not become a universal competence definition.
  5. Omit incidental and entailed claims with explicit reasons. A number’s presence does not establish primality; a prerequisite does not automatically become an additional competency. A narrower claim can make its specialization ancestor unnecessary in a minimal serialization. Organizational ancestry and progression are not such implications.
  6. Represent missingness honestly. Track applicability as required, permitted, excluded or unresolved. Separately record assertion status (asserted/unasserted) and implementation or ontology support. Track projection reasons such as specialization-derived or retained-as-context. An omitted label does not assert its opposite; do not train every omitted facet as a negative class.
A learnable rule record: task selector → included evidence roles → retained facet → exclusion/precedence rule → positive example → nearest negative example. Each assertion or omission should have a stable reason ID and an accessible evidence explanation. This proposal has not yet been evaluated with an LLM.

Current TSPEC-13/14 already favors observable competencies and meaningful Scopes. The improvement is to make conditional applicability and explanations first-class, shared policy data rather than distributing the same interpretation across producers, views, validators and model instructions.

04 / CONCRETE BOUNDARIES

Make the reason visible in the exercise.

Established · numeric expression

Write 3³ ↔ Evaluate 3³

Writing the expression uses the syntax quantities. Evaluation additionally requires 27. The wording changes the mathematical contract, so the quantity set changes for an observable reason. 5.OA.A.2 explicitly distinguishes interpretation from evaluation; 6.EE.A.1 covers numerical powers.

Established · algebra

Solve 3x = 12

Numeric ranges are excluded by the current algebra policy, including bound evaluation. Keep the equation’s mathematical form, requested performance and relevant number-domain constraints. Magnitudes remain generation facts. Enlarging a coefficient does not revive the excluded range facet.

Established · fractions

Recognize 1/2 = 4/8

Independently assessed model part counts 4 and 8 participate. “All fractions are less than 1” is insufficient. Common versus unlike denominator relationships and recognition versus justification remain separate distinctions. Grade 3 NF and Grade 4 NF support these contrasts.

Established · numeral representation

Read 321 / identify its digits

The scalar 321 governs the range; digit glyphs do not automatically become separate numbers. A required sum such as 3100 = 3000 + 100 introduces actual mathematical quantities. The distinction is the requested operation on quantities, not how many symbols appear.

Proposed · analysis/functions

Interpret extrema or intervals of f

Use function family, domain, representation and requested interpretation as the defining facets. Treat elementary magnitude as prerequisite context when it does not define that task’s assessed contract. HSF.IF.B.4–5 supports feature interpretation and domain/context distinctions. This is a prospective policy, not implemented HS target coverage.

Proposed · numerical analysis

Approximate an integral to a tolerance

Do not apply a blanket “advanced mathematics has no numeric difficulty” rule. Precision, tolerance, interval partition, required method and error evidence can be decisive. Keep internal numeric facts; determine relevant annotation facets explicitly. This repository review does not validate a numerical-analysis curriculum or empirical difficulty scale.

Two important boundaries: Ability.AnalyticalCapability also applies to elementary reasoning and cannot act as an analysis cutoff. Also, being outside the current completeness graph is not the same as a ban on a label. Calculus descendants are outside its ordinary context; only explicit exclusions forbid range/sign/zero claims. The proposed broader relevance policy would need its own reviewed implementation.

Mixed tasks need a declared decision: “Find f′(x), then calculate f′(2)” explicitly combines symbolic and numerical demands. Preserve that distinction instead of inferring applicability from the word “analysis” or a small coefficient. Existing algebra exclusions retain precedence. Likewise, interpreting where a derivative is negative concerns function-sign behavior, which is different from the whole-task NumericSign facet.

What these results actually support

  • Keep range information wherever it is a substantive requirement. Global deletion merges within-10/20/100 arithmetic requests. It cannot preserve the original distinctions on its own.
  • Replace proxies before removing them. Two lower-range collision groups involve K.CC.A.1 versus K.CC.A.2. The current given-start practice uses a pragmatic lower-5 cohort. A direct, observable “count from a given start” contract would express the difference more clearly than a magnitude floor; introducing a descriptor would require ontology review.
  • No target collision does not mean no information loss. Base/numeral labels often come from views rather than target requests. Dropping them deletes 7,524 annotations and can violate current completeness/context obligations despite leaving every target signature distinct. Consider a separate context prediction channel, not silent deletion.
  • Specialization deduplication has a small payoff. It removes 219 occurrences (0.42%): 133 VolumeMeasurement, 84 FractionNumbers and 2 CommonDenominator. This is a promising serialization audit, with claim ownership and inference checked first; it is not a major simplification by itself.
  • Absence-label collisions need domain inspection. Targets are partial requests. A missing zero/sign claim is not its opposite, so some merged signatures may reflect authoring asymmetry or legitimate overlap. Compare their admitted generation plans before judging equivalence.
Reproducibility and limitations

The probe uses production target loading, label normalization, ontology specialization/structure traversal and the official local short-label mapper. Every public output label was validated against the pinned vocabulary. The selectors received an independent code review. An initial diagnostic run used the wrong short-name extraction; the accepted run corrected this and added explicit lookup validation. Only the corrected summary is reported here.

For the numeric pilot, also measure cold catalog/matching cost and default-budget coverage performance. Large-domain preparation must not move into imports, metadata compilation or test setup unnoticed. Preserve native ordering, multiplicity and masses; any changed random-draw schedule requires a separately declared migration.

Complexity is not calibrated difficulty. Carrying, denominator relationships, structural depth and precision are objective task features. Their effect on a learner depends on prior knowledge, strategy and presentation. This review supports retaining those features; it does not establish a universal difficulty score. Learner accuracy, time, hints or strategy evidence would be needed for calibration.

Priority: start with the shared numeric adapter. In parallel, specify the applicability matrix and contrast tests. Defer broad label deletion until the separate training-profile experiment demonstrates that meaningful distinctions and contextual truth survive.
